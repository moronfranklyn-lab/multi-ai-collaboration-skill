# 效果验证

只有在用户要求评价方法，或确有流程成本问题时使用。不把每条聊天都变成评估实验。

## 先提出可证伪的问题

例如：“对质量要求接近的同类任务，共享来源与明确交接，能否减少人工协调和返工；减少量是否超过额外阅读、核验与审计成本？”

不要把“所有助手接入成功”“三个模型结论一致”当作效率或正确性的证明。多模型可能共享训练偏差，也可能引用同一错误来源。

## 做最小比较

选低风险、可重复的小任务，先约定相同验收条件。用历史任务回放、隔离环境或可比的新任务比较原流程与新流程；不要为了实验重复真实支付、发消息、发布或业务修改。任务难度、模型版本和操作者经验不同要记录，不能把一次结果泛化。

按实际需要记录：

| 指标 | 为什么看 | 记录边界 |
|---|---|---|
| 人工协调时间 | 用户是否少搬运背景、催办和裁决 | 含阅读交接与处理争议时间 |
| 任务周期 | 是否更快达到同样验收要求 | 区分等待、执行和返工 |
| 纠错与重复工作 | 是否减少事实误用、重复修改与冲突 | 先明确什么算一次错误 |
| 额外成本 | 协作机制本身是否过重 | 含模型、工具调用、审计与维护成本 |
| 可追溯性抽查 | 是否能从交付物回到来源和实际修改 | 抽查真实事件，不能只看字段填满 |

质量要先可比，再谈速度。没有可比基线、样本太少或只测了连通性时，明确证据不足，不编造节省比例。失败案例与缺失数据保留；涉及隐私的原始记录只在受控范围内使用。

## 输出判断

围绕用户当前方案回答四件事：

1. 原方案有哪些只处理表象的部分？没有依据时写明无法判断，不为求新否定原方案。
2. 从事实、目标与限制重新推导的最短路径是什么？可能是保留单助手，只加统一来源；也可能是按可独立验收的交付物并行。
3. 路径成立的前提是什么？例如共享源可访问、授权明确、验收可执行、维护者有可用时间。
4. 第一项最小验证是什么？选一个真实小任务或隔离回放，明确要观察的变化，再决定是否扩大。

若额外成本持续高于收益，应简化字段、合并角色或回到单助手流程。不要为维护方法而强迫任务适应它。
